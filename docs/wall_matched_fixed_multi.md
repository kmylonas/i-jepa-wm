# Matched fixed versus multi-layout Wall run

Open [`notebooks/wall_matched_fixed_multi_colab.ipynb`](../notebooks/wall_matched_fixed_multi_colab.ipynb) in Google Colab, choose a GPU runtime with at least about 95 GiB of free local disk, and run cells in order. The notebook clones the `wall-layout-generalization` GitHub branch and checks out source commit `b493bf89dd67473a94b3cf4681f952e5f6a7318d`; uploading the notebook alone is sufficient. It clones DotWall and checks out commit `0a9492fa12044b852ae9e001cc74604b79c8bb0c`.

The frozen encoder is loaded from `/content/drive/MyDrive/checkpoints/IN1K-vit.h.14-300e.encoder-only.pth.tar`. The notebook copies this checkpoint to the runtime disk; it does not need the full I-JEPA training checkpoint.

The new Drive root is `/content/drive/MyDrive/datasets/wall_matched_fixed_multi_v3`. It is separate from the earlier v2 run, whose checkpoint selection used unseen layouts. Each of its `fixed/` and `multi/` directories receives a manifest, environment config, pilot and full coverage audits, run identity, `world_model/best.pt`, `world_model/last.pt`, validation/test rollout JSON, collision and visual-pair JSON, a default-layout sanity planning JSON, and a completion marker. The final paired planning results are in `matched_planning/matrix_summary.json` and its per-layout JSON files. Drive holds no raw episodes, frames, latent caches, or trajectory sidecars.

The local runtime root is `/content/wall_matched_fixed_multi_v3`. For each model the notebook collects 2,600 episodes (2,000 train, 200 validation, 400 test), audits the full raw dataset, requires the training-only coverage threshold to pass, embeds it with stride 1 in 100-episode batches, and deletes a batch's raw files only after checking the latent shape and sidecar identity. It trains and evaluates the fixed model, verifies its Drive outputs, deletes the entire local fixed dataset/cache, and only then starts the multi dataset. It repeats the cleanup after the multi model. Each dense cache is about 81 GiB; all raw images at once are about 19 GiB. The notebook checks free disk before collection and embedding.

Commands stream stdout and stderr into the Colab cell as they run. Training prints a loss line every 100 steps and an epoch summary after validation; a long validation pass may still have no intermediate loss line.

Both training datasets alternate the correlated-heading `wide` policy, with uniformly sampled primitive-action lengths in `[0.2, 3.5]`, and the doorway-directed `door` policy. The fixed training layout is `[32, 30]`, the simulator default. The multi training layouts are `[24, 32, 40] × [18, 30, 42]`. Each model has 1,000 wide and 1,000 door training episodes; policy type and seed are paired, and each multi training layout alternates the two types. The fixed model's 200 validation episodes use `[32, 30]` with new seeds. The multi model's 200 validation episodes use its nine training layouts with new seeds, spread nearly evenly across layouts. Validation seeds and policy types are paired across models; layouts differ. Both models use identical unseen test assignments. The pilot compares shared wide training actions before full collection; the second full audit compares paired wide actions and shared test actions after the first raw dataset has been removed. Doorway-directed actions can depend on layout and are checked accordingly.

A local pilot with this paired alternating policy recorded 12 doorway crossings in ten fixed-layout training episodes, and 9–20 crossings per layout across 90 multi-layout training episodes. It also verified that the five shared wide training seeds produced identical actions; the five doorway-directed seeds were correctly treated as layout-dependent. These pilot counts do not establish the per-layout full-data threshold. A separate wide-only pilot found only 0–4 doorway crossings per layout, which motivated the policy change.

Both models start from random world-model weights with seed 42, the same frozen I-JEPA encoder, one-step loss, `num_hist=1`, batch size 8, and at most 20 epochs. Their train-only action and state normalization statistics can differ because their training states differ. Each model selects `best.pt` using its own validation episodes from its training layouts. The unseen test layouts do not select either checkpoint. Since validation layout distributions differ, compare validation losses within each model's training run rather than directly between models.

Planning uses position cost, horizon 5, five macro actions executed per plan, 300 CEM candidates, 30 elites, ten iterations, and a primitive-action Euclidean cap of 3.5. The primary comparison uses 50 matched seeds on each of four held-out layouts (200 paired environment episodes). The paired bootstrap resamples 50 seed IDs while keeping each seed's four layouts together. The same 20 seeds on `[32, 30]` provide an in-distribution sanity check. These are proprioceptive models, so planning success alone does not establish vision-only control.

If you stopped the original 100-epoch fixed run after 20 epochs, upload the revised notebook, rerun its setup cells, then run the training cell starting with `run_model("fixed")`. The notebook checks that the unfinished run identity and both checkpoints match this experiment, changes the epoch limit to 20, finishes fixed-model evaluation, then allows `cleanup_model("fixed")` to clear local data before starting the multi model. Running `cleanup_model` alone before evaluation finishes will fail because it requires the result files.

If a Colab runtime resets, raw episodes and caches vanish. Rerun the notebook; the same Drive manifests reconstruct those datasets locally and the world-model trainer resumes from its saved `last.pt`. Before reusing a completed model, the notebook checks its manifest, encoder checksum, pinned source, training settings, checkpoint, and result files against the current run. A reset may require substantial re-embedding time, even when its checkpoint is already on Drive.
